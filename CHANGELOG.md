## [Unreleased]

### Added
- **`handoff --upload <gcode>`**: a sliced job reaches the printer without anyone copying a file by hand. AdvancedStudio gained a guarded upload seam (its ADR-0002); this proposes through it. The last manual step in the chain was a human dragging a file between folders, which is where the wrong file gets used.
- **Upload and print are two proposals, never one.** They are separate effects, and bundling them would hide the second behind approval of the first. Both now carry `design_artifact_sha256`, so the human approving sees which design the job claims to be rather than only a filename — and the studio flags a filename that no longer carries that hash rather than blocking it, since a rename can be legitimate.
- The staged STL is already hash-named, so a slicer output that keeps the stem carries its provenance to the printer for free and stays visible in the file list. That is the durable half of the association; the proposal itself is in-memory with a TTL.
- Automating the *slicing* was investigated and abandoned on evidence rather than assumption: Creality Print 7.2 does carry a Bambu-lineage CLI (confirmed by reading `CrealityPrint_Slicer.dll`), it parses arguments correctly, and it crashes with an access violation on valid ones. The studio does not need to slice — a human slices, which is where ADR-0009 wants a person anyway.
- 60 tests (up from 56), including that `--offline` refuses an upload rather than ignoring it, and that a studio refusal names the action it refused.

- **`compensate` closes the verification loop** (ADR-0011): a recorded comparison becomes a proposed slicer compensation, or a specific refusal to make one. `compensate --comparison <sha256> --max-axis-spread-pct <v> [--propose-to-profile <key>]`.
- **This engine judges whether a compensation is defensible; it does not compute the setting.** AdvancedStudio's calibration calculators already turn a nominal/measured pair into an OrcaSlicer shrinkage percentage and are calibrated against its process research. Computing it here too would give the platform two implementations of one formula, in two languages, free to drift, with no test able to catch it. So the measured pair goes over the wire and the verdict stays here — the split follows what each side actually knows.
- Three refusals, each a real failure mode rather than defensive padding: `WithinScannerNoise` (the deviation is inside the declared scanner accuracy, so a setting from it compensates for the instrument), `AccuracyUndeclared` (no basis to separate signal from instrument — unknown, never "small enough to ignore"), and `AxesDisagree` (X and Y differ by more than the caller's declared threshold, and their mean would be wrong on both axes).
- **Z is never folded into the XY figure.** Orca's Shrinkage (XY) applies to X and Y only; Z deviation has different causes. A test pins that the XY pair is the mean of x and y alone even when Z shrank five times as much.
- **`--max-axis-spread-pct` is declared and has no default.** Found while adding it: `compare`'s advisory output was making the same judgement against a hard-coded `0.5` — a constant deciding a tolerance, which the project rule forbids. It now defers to `compensate` rather than deciding quietly.
- A proposal carries `odc-comparison:<sha256>` as its origin, so a compensation stored in a material profile can be traced back to the scan that produced it. Propose-only (ADR-0009): a human approves it in the studio. A refusal is never proposed, and a test enforces that.
- 56 tests (up from 43). Validated on synthetic prints only — the plumbing is proven, the resulting percentage is not, and that needs a real print and scan.

- **Provenance records the artifact's own dimensions** (ADR-0010, schema `odc/provenance/0.1` → `0.2`). The `artifact` block gains `bbox_mm` and `volume_cubic_mm`. The sidecar previously described only what went *in* — part envelope, scan hash, clearance, wall — so the obvious question a fabricator asks of a design, *does this fit the build volume*, could not be answered from the record that travels with the artifact. Every downstream peer would have needed a mesh parser to answer a question about dimensions. Found while wiring OpenBuildCore's machine capability check to consume ODC output, but it is a gap in the record on its own terms.
- Extents come from the mesh bounding box at float precision and are **not** bounded by voxel size; volume comes from the voxel field and **is**. The two are kept apart deliberately — this is the same distinction the scan-compare significance bug got backwards, now written down where the next reader will find it. Verified on a real run: an 18.00 × 25.50 × 3.10 mm part envelope yields a 23.40 × 30.90 × 5.80 mm artifact, exactly envelope + 2(clearance + wall) and wall + z + clearance.
- `examples/platform-walkthrough` gains a machine-capability step between the enclosure run and fabrication staging, and the chain now reads **inventory → electronics → board → enclosure → machine check → staged**. OpenBuildCore judges the enclosure from its provenance record — `artifact.bbox_mm`, `volume_cubic_mm` — importing nothing from this repo. The peers meet at a file, which is the composition shape ADR-0007 argued for, and it is the first time a peer *consumes* a provenance field rather than merely producing one. Until something depends on a field, "we record provenance" is an untested claim. Real run: a cradle fitted to the 34 × 46 mm board measures 39.6 × 51.6 × 7.03 mm, exactly twice the clearance plus twice the wall larger.
- Rerun byte-identity survives the addition, checked rather than assumed: `CalculateProperties` is deterministic on the same voxel field. 43 tests (up from 41); the new bbox test recomputes expected dimensions from the recorded inputs rather than from the model, so it checks the record against geometry instead of against the code that wrote it.

- Repository seeded: docs skeleton, contribution rules, CI stub, reference-test scaffold.
- `wiki/`: LLM Wiki instantiated (ADR-0006 accepted) — schema, index, log, 8 entity pages, ecosystem map, use-case exploration, open questions.
- ADR-0007: OpenDesignCore is an engine among peers; the Computational Engineering platform is the MCP-composed ecosystem.
- ROADMAP filled: thin thread as "Now"; scan-to-fit and MCP surface as "Next"; explicit non-goals.
- Platform decisions PD-1..PD-6 recorded in `wiki/concepts/platform-decisions.md`; BINGO↔ODC provenance contract drafted (v0).

- Scan-compare verification loop: `compare --design <stl> --scan <stl> --units <u> --voxel-mm <v> [--scan-accuracy-mm <v>]` measures per-axis deviation and volume between a design and a scan of the printed part, records both inputs hash-chained in a canonical-JSON comparison record, and appends a ledger row. Axis spread distinguishes uniform shrinkage (one scale factor is valid) from anisotropic (it is not). 6 tests recover known scale factors from synthetic "prints".
- **Significance is judged against a declared scanner accuracy, not the voxel size.** The first version compared deviation to voxel size, which was wrong: bounding extents come from mesh vertices at float precision and never pass through the voxel grid — voxel size bounds the *volume* figures only. Caught by running the CLI on real board geometry, where it recovered an exact −0.35% on all three axes with zero spread and then called it unresolvable. `--scan-accuracy-mm` is now declared by the caller, never inferred; undeclared means significance is **unknown**, not false, and the run does not count as passed.
- `examples/platform-walkthrough`: one script running all four peers end to end — OpenBuildCore (buildable? shopping list) → OpenCircuitCore (schematic, ERC, BOM, board, DRC, STL) → OpenDesignCore (enclosure fitted to the real board) → fabrication staging. Shells out to each peer's CLI so it tests interfaces, not internals. Satisfies the "at least one example runs end to end" clause of the definition of done.
- ASCII STL import at the mesh boundary. PicoGK 2.2.0 throws `NotImplementedException` for ASCII STL and `kicad-cli pcb export stl` emits exactly that, so the OpenCircuitCore→OpenDesignCore co-design bridge crashed on the first real board. Binary/ASCII is detected by the `84 + 50n` size identity (not the `solid` prefix, which binary files also use); parsing is file I/O only — geometry stays with the kernel. Test asserts both encodings of one geometry yield the same cradle but different recorded scan hashes, since provenance tracks the bytes that arrived.
- MCP surface (`src/OpenDesignCore.Mcp`, stdio, ModelContextProtocol `[2.2.0]`): 7 tools — `list_models`, `list_parts`, `list_runs`, `get_provenance`, `run_enclosure`, `run_cradle` execute; `handoff_to_studio` proposes only. No approval tool exists and a test enforces that (ADR-0009). `McpGuard` refuses voxel sizes outside [0.05, 5] mm, requests over a 2e9 voxel budget, and paths escaping the working root (set with `ODC_ROOT`). 8 new tests incl. DI-level tool discovery; 33 total.
- Scan-to-fit: `run-cradle --stl <path> --units <u> --voxel-mm <v>` imports a scanned mesh at a strict boundary (units declared, AUTO refused; raw scan bytes content-addressed; recentred deterministically via the Matrix4x4 transform — the (scale, offset) overload in PicoGK 2.2.0 has a per-axis-component bug, noted for upstream), then carves a foam-insert-style cradle (`scan-cradle/0.1`): bounding block minus the clearance-offset scan volume up to a split height. Sidecar hash-chains cradle → scan. Resolution floor `min(wall/2, clearance)`. 5 new tests with a synthetic PicoGK-generated scan; 25 total.
- Fabrication handoff: `handoff --run <id> --stage <dir>` stages the artifact + provenance sidecar (hash-named) for slicing, verifies AdvancedStudio answers `GET /api/state`, optionally proposes `print_start` through the studio's propose-only seam and records the confirmation id; `handoffs` table added to the ledger (append-only). `--offline` records `staged-offline` explicitly — degradation is never silent. 5 tests against a loopback studio stub.
- Thin thread runs end to end: `run-enclosure --voxel-mm <v>` builds an open-top enclosure tray around a cited part envelope on headless PicoGK, validates it, exports binary STL, writes a deterministic canonical-JSON provenance sidecar (SHA-256, byte-compatible with Project BINGO's `canonical_json`, verified against Python-generated vectors), content-addresses both into `artifacts/`, and appends the run to `ledger.db` (Microsoft.Data.Sqlite, append-only, `Pooling=False`). Resolution floor enforced (wall >= 2 voxels). 15 tests including rerun byte-identity.
- `data/` reference store: parts + materials namespaces, snake_case JSON, strict loader (`DataStore`) enforcing citations, unknown-field rejection, and positive dimensions; `validate-data` CLI command; first test project (6 tests) activates `dotnet test`. First entries: `parts/esp32-s3-wroom-1` (Espressif datasheet), `materials/pla-generic` (secondary-sourced, TODO(source)).
- Thin-thread solution skeleton: net9.0, PicoGK `[2.2.0]` via NuGet, ShapeKernel submodule pinned to `ShapeKernel-v2.1.0` compiled in a non-strict wrapper project; builds, runs, and formats clean. ADR-0008. Verify commands recorded in CLAUDE.md.
