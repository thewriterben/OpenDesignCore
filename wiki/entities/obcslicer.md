The ecosystem's slicing layer (built and physically proven 2026-08-23; github.com/thewriterben/OBCSlicer). Fills the gap this wiki recorded against [[advancedstudio]] ("slicing deliberately not automated"): slicing is now automated *up to* the propose boundary; approval stays human. Chain: field spec (`obc-field/0.1`) → `fieldengine` (net9.0 + PicoGK 2.2.0, same pinned stack as [[opendesigncore]]) → `obc3mf` (emits OrcaSlicer *project* 3MFs — plain core-spec files import geometry-only; the minimal sufficient project structure was reverse-engineered and delta-debugged to a 22-key `project_settings.config`) → `obcslice` (headless OrcaSlicer wrapper; slice record `obc-slice/0.1`, canonical JSON byte-compatible with ODC/BINGO; verifies the ODC design sidecar's artifact hash against the model *before* slicing) → `stage_for_studio` (`<design12>-<gcode12>.gcode` naming so studio-core's `carries_design_hash` passes) → `propose_upload`/`propose_print` against `/api/propose`. First physical artifact: two-material z-banded cube printed on the K2 Plus, full human-approved audit trail in the studio jobs ledger. Also demonstrated: per-band process overrides (graded infill 80%/10%, 2.94× extrusion ratio — region-scope keys only; temperatures grade via filament slots). OpenVCAD remains a format peer only (non-commercial license); the planned `vdb_grid` field type is the OpenVDB interop seam. BumpMesh headless CLI lives in the stlTexturizer repo (GPL side). Field lesson: K2 CFS lanes map T0→A, T1→B…; an empty lane presents as a false "filament runout".
